1. Introduction

1.1 Purpose

This document provides a comprehensive technical description of the School Management System (SMS), a web-based Software-as-a-Service (SaaS) platform designed for the Tanzanian education system. The system allows multiple schools to manage their academic and administrative operations through a single shared platform.

6. Multi-Tenancy Strategy

6.1 Approach: Shared Database, Row-Level Isolation

All schools share a single database. A school_id column on every major table ensures each school can only access its own rows.

6.2 Login Flow

AuthController::login()
    │
    ├── 1. Find user by username in `users` table
    │         └── Also try: admission number (student login)
    │         └── Also try: child's admission number (parent login)
    │
    ├── 2. Verify password (bcrypt)
    │
    ├── 3. Load school: SELECT * FROM schools WHERE id = user.school_id
    │         └── If status != 'active' → Error: "School suspended"
    │
    ├── 4. Check subscription: SELECT * FROM school_subscriptions
    │         WHERE school_id = ? AND end_date >= CURDATE()
    │         └── If no active subscription → Error: "Subscription expired"
    │
    └── 5. Set session: school_id, school_name, user_id, role, etc.

6.3 Query Isolation

// helpers/auth.php
function currentSchoolId(): ?int {
    return isset($_SESSION['school_id']) ? (int)$_SESSION['school_id'] : null;
}

// Every model automatically adds school filter:
$schoolId = currentSchoolId();
$sql = "SELECT * FROM students WHERE deleted_at IS NULL";
if ($schoolId) {
    $sql .= " AND school_id = ?";
    $params[] = $schoolId;
}

10. AWS Deployment & Load Balancing

10.1 Why Database Sessions?

PHP normally saves session data as files on the local server disk. With a Load Balancer directing traffic across multiple EC2 instances, a user logged in on EC2 #1 would be logged out if redirected to EC2 #2 (their session file doesn't exist there).

Problem (old approach): Sessions saved as files on EC2 local disk → Load Balancer breaks sessions
Solution (implemented): Sessions saved to RDS MySQL → all EC2 instances share the same session data

10.2 DatabaseSessionHandler

A custom class DatabaseSessionHandler implements PHP's built-in SessionHandlerInterface:

MethodSQL Operation
read($id)SELECT data FROM sessions WHERE id = ?
write($id, $data)INSERT ... ON DUPLICATE KEY UPDATE data = ?, last_accessed = NOW()
destroy($id)DELETE FROM sessions WHERE id = ?
gc($maxLifetime)DELETE FROM sessions WHERE last_accessed < NOW() - INTERVAL ? SECOND

10.3 Stateless Application Properties

DependencyStatusDetails

Local File Uploads✅ Not UsedNo file upload features — no local storage dependency
In-Memory State✅ NoneAll state lives in MySQL — safe to run on multiple EC2 instances

11. AzamPay Payment Integration

11.1 Integration Type

The system integrates with AzamPay USSD Push — a mobile money payment system used in Tanzania. Supported providers: M-Pesa, TigoPesa, Airtel Money, Halopesa.

11.2 Payment Flow

StepActorAction
1Student/ParentClicks "Pay Now" on invoice — selects provider, enters phone number
2SystemCreates payment_transactions record (status: initiated)
3System → AzamPaySends USSD Push request to AzamPay API with amount + phone number
4AzamPay → PhoneUSSD prompt appears on student/parent's phone: "Enter PIN to pay TZS X,XXX"
5Student/ParentEnters PIN on phone to authorize payment
6AzamPay → SystemSends webhook POST to /api/azampay/webhook
7SystemUpdates transaction status → "success"
8SystemUpdates invoice amount_paid, creates fee_payments receipt

11.3 API Endpoints

EndpointMethodPurpose
/api/azampay/checkoutPOSTInitiate payment — sent from application to AzamPay
/api/azampay/webhookPOSTReceive payment confirmation callback from AzamPay
Status: Mock implementation is in place and fully functional for testing. To go live, replace the mock API call in PaymentController::checkout() with actual AzamPay Merchant credentials and production endpoint URL.

13. Request Lifecycle

USER opens: https://domain.com/school-management-system/public/students
                │
                │ .htaccess rewrites to public/index.php?url=students
                ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                    public/index.php (Front Controller)                  │
│                                                                         │
│  Step 1: Bootstrap                                                      │
│    require config/app.php         → APP_NAME, BASE_URL, grading fns    │
│    require config/database.php    → PDO Singleton ready                 │
│    require helpers/session.php    → Register DatabaseSessionHandler     │
│    require helpers/auth.php       → requireLogin, requireRole, etc.     │
│    require helpers/functions.php  → sanitize, redirect, flash, etc.     │
│                                                                         │
│  Step 2: Session Start                                                  │
│    startSession()                 → DatabaseSessionHandler::read()      │
│                                   → SELECT data FROM sessions WHERE id=?│
│                                   → $_SESSION loaded from RDS           │
│                                                                         │
│  Step 3: Route Resolution                                               │
│    require config/routes.php      → load $routes array                  │
│    $url = 'students'              → match $routes['students']            │
│    → ['StudentController', 'index']                                     │
│                                                                         │
│  Step 4: Controller Dispatch                                            │
│    require controllers/StudentController.php                            │
│    $controller = new StudentController()                                │
│      → __construct() → requireRole(['super_admin','school_admin'])      │
│        → Checks $_SESSION['role'] → OK                                  │
│    $controller->index()                                                 │
│                                                                         │
│  Step 5: Model + View                                                   │
│    $model = new Student()                                               │
│    $students = $model->getAll()                                         │
│      → SQL: SELECT ... WHERE deleted_at IS NULL AND school_id = 1       │
│      → Returns only current school's students                           │
│    require views/layouts/header.php  (sidebar + navbar)                 │
│    require views/students/index.php  (student table)                    │
│    require views/layouts/footer.php  (Bootstrap JS)                     │
└─────────────────────────────────────────────────────────────────────────┘
                │
                ▼
        HTML Response → Browser
